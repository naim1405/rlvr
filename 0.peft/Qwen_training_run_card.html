Qwen3 training run card — Griffith gpuq2, 1× A100 80 GB

Pick a row → request those PBS resources → paste that model’s env block into the PBS body → smoke first, then train, then infer. This card is for the current stage‑0 PEFT recipe in 0.peft/: bf16 LoRA (r=32, alpha=64, dropout 0.05, all *_proj), AdamW, 34,300 train rows, global batch 32, 2 epochs ≈ 2,144 optimizer steps. Text‑only dense Qwen3 models only; the 32B row is included as a hard stop.

How to use this card (read once)

  1. Resources in the table are the PBS request for the train job: always 1 node, ngpus=1 (A100 80 GB), queue gpuq2, plus the row’s ncpus / mem / walltime. “Required VRAM” = expected peak on that one GPU (you cannot request a fraction of a GPU here).
  2. Time shows expected runtime (estimate) → walltime to request. Estimates assume ≈600 capped tokens/row at max_length=2048 (dataset p50/p90 = 267/1343 tokens; 2048 truncates ≈7.5% of rows) ≈ 41M token positions over 2 epochs. Correct the request from your smoke timing (formula below) — do not treat any number here as measured.
  3. Knobs are environment variables already supported by run_peft_training.sh → render_recipe.py. Fixed by the recipe (not per‑row knobs): LoRA target/rank/alpha/dropout, bf16, FSDP2 (TP=CP=1), AdamW betas/eps/weight‑decay, seed 1111, validation split 2%, no system prompt. Changing LoRA rank/targets means editing recipe.yaml — don’t do it casually mid‑project.
  4. Smoke gate (separate job, before train): 1 GPU / 4 CPU / row’s train RAM / 2 h. Run the standard smoke first. For 8B/14B (and ideally 4B), also run a production‑shape smoke (recipe below the table) to measure true peak VRAM and sec/step at length 2048.
  5. Use a distinct CHECKPOINT_DIR and RUN_NAME per model/knob set so rendered recipes, logs and adapters never mix. Keep MODEL_ID identical across smoke → train → infer → merge → RLVR.
Walltime from smoke: from a production‑shape smoke, take steady‑state seconds/optimizer‑step s and request hours ≈ s × 2144 × 1.5 ÷ 3600 + 0.5 (load/validation/checkpoint slack), rounded up. If that exceeds the card’s request, use the formula value.

Smoke gate for your chosen row (run before every first train)

Standard smoke first (proves container/GPU/dataset/checkpointing). PBS resources: 1 GPU / 4 CPU / train‑row RAM / 2 h.

export MODEL_ID=<row MODEL_ID>
export SIF_PATH=<repo>/Containers/nemo-automodel_26.04.00.sif
export RUN_NAME=<tag>-smoke
bash <repo>/0.peft/run_peft_training.sh smoke

Then, for 4B/8B/14B, a production‑shape smoke (measures real peak + sec/step at length 2048; still only a 2,048‑row subset because smoke mode caps epochs/checkpointing unless you override them — so set only these shape knobs):

export MODEL_ID=<row MODEL_ID>
export SIF_PATH=<repo>/Containers/nemo-automodel_26.04.00.sif
export RUN_NAME=<tag>-shape-smoke
export CHECKPOINT_DIR=/workspace/rlvr/0.peft/checkpoints-smoke-<tag>
export MAX_LENGTH=2048
export LOCAL_BATCH_SIZE=<row value>
export GLOBAL_BATCH_SIZE=32
export GROUP_BY_LENGTH=<row value>
export NUM_SAMPLES_LIMIT=2048
# Deliberately do NOT set NUM_EPOCHS / CKPT_EVERY_STEPS / VAL_EVERY_STEPS here.
bash <repo>/0.peft/run_peft_training.sh smoke

Record: rendered recipe (0.peft/runs/recipes/smoke-*.yaml), peak VRAM from the log, and steady sec/step. Apply the walltime formula and the headroom rules in each row’s “Extra” cell. Format‑check the smoke adapter with the same MODEL_ID/CHECKPOINT_DIR via run_peft_training.sh infer before spending a train slot.

OOM fallback ladder (in order; change one thing, fresh RUN_NAME): (1) confirm PYTORCH_ALLOC_CONF=expandable_segments:True is set; (2) USE_TRITON=false (frees kernel workspace, slower); (3) MAX_LENGTH=1536 (truncation rises modestly); (4) GROUP_BY_LENGTH=false if failures look fragmentation/order‑related rather than at a single max‑length sample; (5) only then reconsider the model size. Never “fix” OOM by raising host RAM — that is a different memory.

Copy‑paste train blocks (PBS body payload per model)

Replace <repo> with the cluster checkout path. Each block assumes dataset extracted and SIF built (one‑time setup in the handoff). After a successful train, run bash <repo>/0.peft/run_peft_training.sh infer in a job with the same MODEL_ID and CHECKPOINT_DIR (resources: 1 GPU / 4 CPU / train‑row RAM / 2 h). If the model was prefetched and compute nodes are offline, add export HF_HUB_OFFLINE=1.

What “done” looks like (every row)

  • Train exit 0; ≈2,144 steps; finite/decreasing loss in 0.peft/logs/train-*.log.
  • Adapter at checkpoints-<tag>/epoch_*/model/ (adapter_config.json + safetensors) — this model/ dir is the deliverable to archive/upload/merge.
  • infer summary shows format PASS with the same MODEL_ID.
  • Keep with the adapter: rendered recipe 0.peft/runs/recipes/train-<RUN_NAME>.yaml, the train log, exact MODEL_ID, and git commit. Copy out of scratch before any purge window.
  • If you later change LR/batch/length, that is a new run: new RUN_NAME + new CHECKPOINT_DIR.

Decision shortcut

  • First cluster run: 0.6B row, exactly as written.
  • Default final model: 4B — best insurance for the later one‑GPU RLVR stage.
  • If PEFT quality is the priority and you’ll validate RLVR separately: 8B.
  • 14B only with a clean production‑shape smoke (peak ≤72 GB), the 72 h request (or formula value), and acceptance that downstream GRPO may not follow on this cluster shape.

Basis: bf16 weights = params × 2 B; LoRA trainables computed from official Qwen3 config shapes at r=32 on q/k/v/o/gate/up/down; activation allowance for no‑checkpointing training at len 2048; dataset token stats from Tuning.md (p50 267 / p90 1343 / p95 3404; 2048 truncates ≈7.5%). All VRAM/time figures are pre‑smoke planning estimates for this recipe — the production‑shape smoke replaces them with measurements.
